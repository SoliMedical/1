# Soli Medical PWA

هذه الحزمة هي النسخة المستقلة من نظام Soli Medical، وتحتوي على ملف HTML واحد يعمل كتطبيق PWA قابل للتثبيت على الهاتف والكمبيوتر.

## النشر على GitHub Pages

ارفع محتويات هذه الحزمة إلى جذر مستودع GitHub جديد، ثم افتح **Settings → Pages**. اختر **Deploy from a branch**، وحدد الفرع الذي رفعت إليه الملفات والمجلد **/(root)**، ثم احفظ الإعدادات. بعد اكتمال النشر افتح الرابط باستخدام HTTPS؛ Service Worker والتثبيت يحتاجان إلى سياق آمن.

لا تغيّر أسماء الملفات أو مجلد assets. تم إعداد الروابط بصيغة نسبية حتى تعمل الصفحة سواء نُشرت على نطاق GitHub الرئيسي أو داخل مسار مستودع.

## الملفات الأساسية

| الملف | الوظيفة |
|---|---|
| index.html | النظام الكامل مع إضافة PWA وشاشة البداية وشريط التثبيت |
| manifest.webmanifest | اسم التطبيق، الأيقونة، اللون، ووضع العرض المستقل |
| sw.js | التخزين المؤقت والعمل دون اتصال |
| firebase-config.js | إعداد Firebase الخاص بهذه النسخة والعيادة |
| assets/ | أيقونة التطبيق وخلفية شاشة البداية والنمط البصري |

## Firebase والمزامنة السحابية

إعداد Firebase موجود في الملف `firebase-config.js` وليس داخل `index.html`. عند تجهيز نسخة لعيادة جديدة، انسخ الحزمة ثم استبدل قيم `window.SOLI_FIREBASE_CONFIG` بإعدادات مشروع Firebase الخاص بتلك العيادة. لا تضع كلمات مرور أو مفاتيح Admin SDK في هذا الملف؛ إعدادات Web الظاهرة مخصصة للتطبيق فقط.

لإنشاء نسخة عميل جديدة: أنشئ مشروع Firebase مستقلاً، أضف Web App، فعّل **Authentication → Sign-in method → Email/Password**، فعّل Firestore، وأضف نطاق GitHub Pages إلى **Authorized domains**. بعد ذلك استبدل كائن الإعداد في `firebase-config.js` قبل النشر.

تسجيل الدخول في الإصدار الحالي يتم من خلال Firebase Authentication فقط: يمكن للمستخدم كتابة البريد الإلكتروني الموجود في Firebase، أو اسم الحساب القديم المدعوم مثل `admin` الذي يحوّله التطبيق إلى البريد المرتبط به، ثم يكتب كلمة مرور Firebase. لا تمنح قيمة `localStorage` أو أي كلمة مرور قديمة أو جلسة محلية صلاحية الدخول. بعد نجاح Firebase Auth يتحقق التطبيق من عضوية العيادة النشطة ويربطها ببطاقة المستخدم عبر البريد أو `firebaseUid`، ثم تبدأ مزامنة Firestore.

لا يحتاج نشر GitHub Pages إلى مفتاح Admin SDK؛ إعدادات Web الموجودة في `firebase-config.js` عامة ومصممة للعميل. أي مفتاح Admin SDK أو JSON لحساب خدمة يجب أن يبقى في خادم الإدارة أو في GitHub Actions Secret مخصص لمهمة إدارية، ولا يوضع في `index.html` أو `firebase-config.js` أو `localStorage`. Workflow النشر الحالي لا يقرأ `FIREBASE_SERVICE_ACCOUNT_JSON`، لذلك لا تضف السر إلى Pages إلا إذا أضفت مهمة تحقق إدارية صريحة.

استخدم قواعد Firestore الموجودة في `firestore.rules` ولا تستبدلها بقواعد عامة تسمح لكل مستخدم بالوصول إلى كل البيانات. اختبر حسابين مختلفين بالبريد وكلمة مرور Firebase من جهازين، وتحقق من ظهور العضويات النشطة والمزامنة. وللحماية من فقد البيانات، استخدم بطاقة **النسخ الاحتياطي والاستعادة اليدوية** داخل إعدادات النظام لتنزيل ملف JSON وحفظه في مكان آمن؛ الملف قابل للقراءة ويحتوي بيانات العيادة، لذلك لا تشاركه عبر قنوات عامة.

## التشغيل المحلي

لا تفتح index.html مباشرة من نظام الملفات إذا أردت اختبار التثبيت والعمل دون اتصال. استخدم خادمًا محليًا بسيطًا، مثل الأمر التالي:

python3 -m http.server 8080

ثم افتح http://localhost:8080 في المتصفح.
