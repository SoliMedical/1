# إضافة الاشتراك داخل Soli Medical

**الحالة الحالية:** صفحة تسعير وتجربة توضيحية فقط؛ لا يوجد تحصيل أو تفعيل اشتراك آلي.

## ما تم إضافته الآن

- رابط عام للتسعير: `?pricing` أو `#pricing`.
- رابط من شاشة الدخول باسم «عرض خطط الاشتراك والتجربة».
- باقات إطلاق المنصورة: تجربة 14 يوماً، شهري 250 جنيهاً، وسنوي 2,500 جنيه.
- إشعار صريح بأن طلب التجربة والدفع لم يفعّلا بعد.

## مراحل إضافة الميزة الفعلية

| المرحلة | ما يُبنى | الضابط الأساسي |
|---|---|---|
| 1. طلب تجربة | جدول `trial_requests` وخدمة خادمية لإنشاء الطلب، ثم مراجعة إدارية وتفعيل حساب العيادة. | لا تُحفظ بيانات مرضى في طلب التجربة، ولا يعتمد التفعيل على عنوان URL فقط. |
| 2. حالة اشتراك | جدول `subscriptions` يضم الخطة والحالة وتاريخ البداية والنهاية وفترة السماح ومعرف مزود الدفع فقط. | الخادم هو مصدر الحقيقة؛ لا تحفظ حالة مدفوعة في localStorage أو Firebase كدليل دفع. |
| 3. دفع مستضاف | إنشاء رابط/جلسة دفع Paymob من الخادم فقط. | لا يستقبل التطبيق رقم البطاقة أو CVV أو token الدفع. |
| 4. Webhook موثق | خدمة خادمية تتحقق من توقيع حدث Paymob، ثم تُحدّث الاشتراك في معاملة واحدة. | لا يُفعّل الوصول من صفحة نجاح المتصفح أو لقطة شاشة التحويل. |
| 5. فرض الصلاحية | حارس خادمي للتحرير وإنشاء المرضى والروشتة؛ عند الانتهاء يبقى الحساب للقراءة والتصدير فقط. | لا حذف تلقائي لبيانات المرضى، ولا منع للتصدير. |
| 6. التشغيل | رسائل قبل الانتهاء وتجديد وإيصالات وسجل تدقيق ودعم. | مراجعة سياسة الخصوصية والشروط والمحامي/المحاسب المصري قبل أول تحصيل. |

## التسلسل الموصى به

ابدأ بتجربة وطلب يدوي موثق، ثم رابط دفع Paymob يدوي لأول 10–20 طبيباً. بعد إثبات الاستعمال والدفع، أضف الاشتراك المتكرر وwebhook الموّقع. لا تُفعّل المرحلة التالية قبل اختبار فشل التحصيل وإعادة المحاولة وفترة السماح وحالة القراءة فقط واستعادة البيانات.
